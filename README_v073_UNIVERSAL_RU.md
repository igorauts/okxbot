# OKX Grid Bot v0.7.3 — единый BTC / ETH / SOL

Публичный исходный код универсального LONG / CROSS grid-бота на OKX для `BTC-USDT-SWAP`, `ETH-USDT-SWAP`, `SOL-USDT-SWAP`. **Один движок `okx_bot073.py` и один менеджер `okxbot` для всех экземпляров.** Отдельные версии на разные монеты не нужны.

## Что входит

- `okx_bot073.py` — торговый движок, пост-онли BUY с прикреплёнными LIMIT TP, виртуальные TP, подтверждаемое агрегированное reduce-only MARKET закрытие.
- `okxbot.py` — менеджер независимых экземпляров, старт после read-only аудита и явного подтверждения, Pause/Soft/Hard/Panic, статистика и клонирование завершённого экземпляра.
- `okx_setup068.py` — интерактивный мастер создания **новых** экземпляров BTC/ETH/SOL; получает точные параметры контракта, минимальный лот, шаг цены и VIP-комиссию из OKX. Создаёт бот с `live_trading=false`.
- `okx_execution_observer073.py` — универсальный, локальный, read-only наблюдатель без API OKX. Поддерживает Burst и Execution в отдельных режимах.
- `okx_monitor073.py` — управление необязательными observer-сервисами **по экземпляру**.
- Исторические двигатели/релизы до v0.7.2 остаются в репозитории для просмотра и совместимости. Публикация не переключает существующие процессы.

## Независимые торговые настройки (при создании)

| Ключ `config.json` | По умолчанию | Допустимо | Смысл |
|---|---:|---:|---|
| `active_buy_orders` | 25 | 1–25 | Целевое число активных BUY |
| `buy_buffer_orders` | 5 | 0–5 | Временные BUY сверх цели (общая граница 30) |
| `buy_cancel_protect_steps` | 3 | 0–10 | Зона запрета отмены BUY вокруг свежего BID **в шагах сетки** |
| `active_tp_orders`, `real_tp_target` | 25 | 1–25 | Норма реальных TP на бирже |
| `tp_buffer_orders` | 30 | 0–30 | Временные дополнительные прикреплённые SELL TP, максимум 55 вместе с целью |
| `grid_step`, `take_profit`, `order_size` | выбираются | спецификация OKX | Стратегия конкретного бота |

Это две **разные** настройки: временные +5 BUY не означают радиус защиты в пять шагов. Например, ETH шаг $0.50 и защита 3 шага ⇒ отмены не производятся внутри ±$1.50 BID. SOL шаг $0.03 ⇒ ±$0.09. Для BTC правило автоматически зависит от выбранного шага BTC-грида.

SELL TP Buffer: при бурсте прикреплённые ордера могут временно увеличить число реальных TP. После 1.5 сек тишины движок постепенно уменьшает их до базового количества: по одному, интервал запросов отмен не менее 100 мс, в первую очередь наиболее далёкие от BID; ближайшие базовые TP защищены. Биржа может создать TP сама быстрее процесса очистки, поэтому максимальный буфер — **целевой порог**, а не мгновенная гарантия предела. При состоянии неопределённости биржи движок должен останавливаться на сверку.

## Менеджер и мониторы

После установки менеджера:

```bash
okxbot new                                 # выбрать BTC, ETH или SOL, создать отдельный экземпляр
okxbot list
okxbot monitor "ИМЯ" burst on              # только выбранный бот
okxbot monitor "ИМЯ" execution on
okxbot monitor "ИМЯ" burst status
okxbot monitor "ИМЯ" execution report
okxbot monitor "ИМЯ" burst off
okxbot monitor "ИМЯ" execution off
```

В интерактивном меню выбранного бота есть переключатели `Burst Monitor: ON/OFF` и `Execution Monitor: ON/OFF`. **По умолчанию оба выключены.** Они стартуют отдельными systemd-процессами и никак не переключают торговые службы. Для отдельно установленного экземпляра используются его `root`, `systemd service` и конфигурация; привязок к пользовательским каталогам ETH или SOL нет.

Мониторы ведут локальные события/состояние и выборочные журналы. Не используют API-ключи и не отправляют запросы ордеров. Они **не подтверждают** независимым способом реальную позицию, комиссии и каждое исполнение OKX. Для такого подтверждения требуется отдельный контролируемый read-only аудит OKX.

## Публикация ≠ деплой

Публикация GitHub-релиза добавляет исходники, changelog, тесты и архив. **Никаких остановок, перезапусков или обновлений уже запущенных ETH/SOL на VPS.** У существующих экземпляров остаются собственные файлы и процессы. Установка/обновление менеджера — отдельное осознанное действие.

Для **новой** установки из обновлённого репозитория:

```bash
sudo bash install.sh
okxbot new
```

Режим нового бота `live_trading=false`; стартует только после успешной биржевой проверки и буквального подтверждения в менеджере. Один бот на инструмент в NET-режиме для одной учётной записи.

## Безопасность и тесты

- 74 прежних офлайн-регрессионных теста движка + 30 тестов универсальности и read-only наблюдения (всего **104** автоматических теста).
- Тестовые конфигурации BTC/ETH/SOL созданы синтетически и **не подтверждают** живую торговлю BTC.
- ETH и SOL v0.7.3 ранее были развернуты в отдельных LIVE-сборках, но объединённый универсальный файл не переключался на LIVE автоматически.
- До миграции работающего экземпляра — backup + сверка всех BUY, REAL/virtual SELL TP и нетто-позиции OKX в режиме read-only.
- Никакие `.env`, ключи, SQLite, `config.json`, логи, снимки состояния или реальные истории сделок не должны публиковаться.
- Скрипт `publish_okx_v073.sh` работает с **чистым временным git-клоном**. Он не устанавливает менеджер и не трогает торговые службы.

## Ограничения

Это программное обеспечение для реальной торговли с риском потери средств. Автотесты не гарантируют корректность исполнения в условиях биржевых задержек или резкой волатильности. Несовпадения в REST/WS, неизвестные ответы на POST и неполная история должны приводить к безопасной остановке размещений, а не к слепым повторам.
