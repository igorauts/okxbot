# OKX Funding Collector

Independent, GET-only account statistics; no trading engine, Reader or Governor changes.

- Local schedule check once per minute; normal GET collection remains hourly at :05 UTC (24-hour overlap), with daily 7-day reconciliation. Terminal accounting uses the last possible hourly settlement window (exclusive end at :01 UTC), not coverage through PANIC_DONE. A complete local proof gives a zero-GET fast path. A missing covered window is fetched only after its settlement minute; terminal-only collection does not refresh live snapshots. Regular hourly collection retains its existing 120-second freshness cushion. Idle checks make no OKX requests and print no IDLE JSON. Stable idle inventory is cached by nonsecret file metadata, not credential contents. Initial backfill and gap recovery use the bills archive within available history.
- Uses the existing single-account credentials and registry. Counts nonterminal bots (including stopped bots) by instrument and creation timestamp. Terminal identities are attested against the immutable engine state and accounting, bound account credentials and non-overlapping instrument lifetimes. The final funding record is retained independently of live snapshots and is not overwritten after confirmation.
- SQLite WAL, exact signed Decimal amounts, billId deduplication, atomic snapshots, seven daily backups on the VPS. Retains prior sums on failures; quarantines incompatible records and isolates instrument-level problems. No funding-based trading decisions.
- Manager and Telegram read the same locally confirmed terminal funding. PANIC does not wait to flatten the position; its single financial final uses the already covered proof immediately or waits at most 90 seconds from PANIC_DONE for the targeted collection. On failure or deadline it reports the verified trading result and explicitly unconfirmed Funding with a reason. The minute timer may delay a targeted GET until its next tick. No Telegram exchange credential reads or requests. The durable hourly proof is retained even if a successor replaces the live snapshot; the Collector freezes the terminal record, and contradictions are surfaced rather than silently replaced. No historical PANIC replay or corrective funding message. HARD shows funding only for the bot lifetime and does not claim final PnL for an open position; funding after HARD is not included. A PANIC inside a settlement minute may include an actual late-posted bill in that minute only with an isolated lifetime; an overlapping successor or unresolved attribution blocks finalization. No assumption that the nominal hour is the actual assessment instant. OKX documents settlement assessment up to a minute; the API does not provide a per-bot assessment identity or a guaranteed publication SLA. A later ledger contradiction is reported as unconfirmed. Manager reads ready active values locally and adds funding to the existing reconciled total PnL. Only the funding dot is colored in the curses viewer.

## Deployment (explicit operator action)

From this directory, review `systemd/paths.conf.example` against the manager's real registry and base directory. Use the existing credentials in the bot directories; never copy them into a release. Run offline tests before deployment: `python3 -B -m unittest discover -v`.

For a new installation only, as root, after verifying no conflicting files or services exist:

1. Create `/opt/okx-funding`, `/etc/okx-funding` and `/srv/okx-funding` with mode 0700. Copy `funding/okx_funding_backup.py`, `funding/okx_funding_collector.py` and the canonical root `okx_funding_ledger.py`, `okx_funding_view.py` into `/opt/okx-funding` (mode 0600). The deployment map in `install_manifest.json` defines these sources. To assemble their verified copies into a new local staging directory, run `python3 -B tools/export_component.py funding --out /tmp/okx-funding-stage` from the source root. This does not install or restart anything. Set `/etc/okx-funding/paths.conf` from the reviewed example (mode 0600).
2. From `/opt/okx-funding`, run `nice -n 19 ionice -c 3 python3 -B -E -s okx_funding_collector.py --base /root/okx --registry /root/okx/.okxbot_registry.json --systemd-dir /etc/systemd/system --data-dir /srv/okx-funding --mode backfill` (adjust paths to match the reviewed configuration). Verify PASS, published snapshots, backup, and SQLite integrity before proceeding. This makes authenticated GET requests only.
3. Install the two systemd units under `/etc/systemd/system` (0644), run `systemd-analyze verify` on both, then `systemctl daemon-reload`. Start only `okx-funding-collector.service` once and inspect its result and journal. Enable the timer only after success: `systemctl enable --now okx-funding-collector.timer`.

Existing installations: do not reset or replace the database. Before enabling the updated Telegram monitor, deploy the pinned Collector/ledger/view and run an explicit successful --mode update to seed complete per-instance proofs; verify the proof inventory against eligible active bots and the existing ledger. Verify the minute timer separately. The fast path is not available to a legacy snapshot without an attested proof. Do not overwrite an existing configuration or units blindly. The manager-only release must be installed using the project's normal verified maintenance procedure. Collector sources in this directory are identical to the deployed standalone files; root-level reader modules are identical copies for the manager. No automated deployment is performed by publishing this release.

The public fixture is synthetic (identifiers, instruments and amounts replaced); it retains the observed response shape, equal timestamps, signs and pagination pattern. Live history, credentials, logs and backups are not included. The benchmark is synthetic; run `PYTHONPATH="$PWD:$PWD/funding" python3 -B tests/funding/benchmark_funding.py` from the repository root locally if desired.
