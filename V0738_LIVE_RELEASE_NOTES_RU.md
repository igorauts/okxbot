# OKX Grid Bot v0.7.38 — LIVE-verified (2026-10-28 UTC)

## Публикуемый пакет и накопленные изменения

Публичный релиз **v0.7.38**, торговый движок **v0.7.38**, оба номера состоят из трёх частей. В публичном GitHub до этого был **v0.7.34**, поэтому пакет включает накопленные изменения v0.7.35–v0.7.38. После первоначального OFFLINE RC4 в финальный пакет внесён только UI-патч меню пар (BEAT, CAP, INIT, BLUR, DOS) и документация о завершённой LIVE-проверке. SHA256 торгового `okx_bot.py` не меняется.

## v0.7.38 — экономный событийный цикл

- Тихая резервная REST-сверка позиции каждые **5–5,8 сек** с устойчивым небольшим джиттером между ботами; независимые защитные дедлайны и немедленные события WS сохраняются.
- Устранена гонка: private `orders` event во время REST-сверки / непосредственно перед BUY POST требует новую сверку; при смене поколения WS решение о новом BUY блокируется.
- Контроль private/public WebSocket (subscribe и ping/pong) предотвращает новые BUY при деградации канала. Автоматический возврат на ежесекундный REST при сбоях WS не включён.
- PANIC/HARD при изменении режима во время REST-ошибки не ждёт трёхсекундный recovery-backoff.
- Не менялись торговая стратегия, финансовые функции POST/CANCEL/PANIC, реальный/виртуальный TP, Shared Reader, Priority FIFO и Telegram торговое управление (его нет).
- `okx_setup_presets.py`: в мастер добавлены **BEAT, CAP, INIT, BLUR и DOS**. Это подсказки меню, не whitelist движка; контракт валидируется у OKX.

## v0.7.35–v0.7.37 — накопленные изменения

- v0.7.35: стабильность повторных WS wake на TP, Reader watchdog, устойчивое Telegram оповещение, финансовые проверки и телеметрия.
- v0.7.36: динамическая GET-free регистрация новых/клонированных ботов в Shared Position Reader, read-only `Reader Diagnostics`, Telegram BYPASS/RECOVERED; движок v0.7.35 без изменений.
- v0.7.37: атрибуция источников wake (`timer/private/grid/...`) для измерения причин позиционной сверки; диагностика без изменения финансовых правил.
- v0.7.38: минимальная 5-секундная схема сверки, защита от устаревшего REST снимка и WS-гигиена.

## Границы проверки

- Реальные BUY, LIMIT TP и MARKET SELL подтверждены локальными логами и указанными оператором наблюдениями. Это **не независимый новый финансовый аудит всех биржевых позиций** на момент публикации.
- Не проводились намеренные LIVE отключения Reader/WS; такие fault injection тесты пройдены офлайн. `mixed-fifo` активен, **Priority FIFO OFF**. Архивные боты не запускаются.
- Telegram не имеет команд управления торговлей; GitHub публикация **не изменяет LIVE-файлы, не вызывает OKX GET/POST и не перезапускает systemd службы**.
- Офлайн full `run_checks.sh` (в том числе chaos интеграция) и ZIP/manifest SHA256 выполняются для публикуемого пакета; исторические документы RC2/RC3/RC4 остаются с пометками OFFLINE как записи об этапах разработки.
