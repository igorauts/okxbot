# OKX Grid Bot v0.7.32 — согласованные финансовые снимки (офлайн RC1)

Статус: **OFFLINE RC1 / НЕ ДЛЯ ПРЯМОГО LIVE-ЗАПУСКА**. Исходная база — RC2 v0.7.31 + применённый Telegram-only hotfix с одним цветным индикатором. На VPS и в GitHub изменений этим архивом не выполнялось.

## Причина

При высокой интенсивности сделок StatsWorker захватывал `bot_state.json`, получал подтверждённые fills и затем отвергал **любой** снимок, если финансовая сигнатура state изменилась за время REST. Одновременно проверка `pnl.total()` сравнивала текущую сумму всего финансового журнала с **историческим** снимком, хотя в журнал уже могли попасть новые закрытия. Поэтому ZEC и DOOD могли не обновлять `stats.json` десятки минут, сохраняя рабочую торговлю.

## Исправления

1. Фиксируем торговый state, состав архивных циклов и BID **до** REST-запросов; время `generated_at_unix` и `stats_financial_anchor.at` означает время получения исходного снимка, а не окончания расчёта. Новый отчёт не выглядит более свежим, чем он есть.
2. При возврате fills из SQLite/REST отсекаем исполнения, произошедшие сверх количества, подтверждённого на момент снимка. **Только целые реальные биржевые fills; ни дробления строки, ни моделирования цен или комиссий**. Дубликаты `billId`, неизвестные ордера, нехватка исполнений, пересечение количественной границы отдельным fill — отказ, предыдущая статистика остаётся.
3. Финансовую сумму сверяем с PnL-ledger только по CLOSED циклам зафиксированного снимка. Новые закрытые циклы, появившиеся в ledger после начала расчёта, не включаются. Недостающая запись ledger или несовпадение > 1e-8 USDT — отказ.
4. При неудаче фонового расчёта StatsWorker повторяет проверку не ранее чем через 60 секунд; при успехе сохраняется штатный интервал 600 секунд, а при новых fills допускается перепроверка с ограничением частоты в 60 секунд.
5. Не изменены: BUY/TP/MARKET/PANIC/HARD, постоянные общие FIFO, лимит 8 запросов / 2.1 с, окно 150 мс, REST торговых команд, позиции, ордера и порядок durable intent. Формат Telegram MARKET SELL, установленный hotfix, включён в новую базу.

## Ограничения / условия для LIVE

- Полный offline `run_checks.sh` и тесты из `tests/test_financial_snapshot_0732.py` необходимо прогнать на опубликованном артефакте. Результат успешного офлайн тестирования не подтверждает работоспособность на реальном VPS с изменяющимися позициями.
- Проверить обновлятор и hash-пакета на staging **до** команд STOP. Для будущего LIVE перехода сначала ZEC, остальные боты оставить как есть до успешной GET-only проверки.
- При нестабильных или отсутствующих исходных fills PnL по-прежнему показывает старый подтверждённый снимок/`н/д`; исправление не подавляет финансовые ошибки и не подделывает свежесть.
- При интенсивном непрерывном исполнении и многократных неделимых fills, пересекающих snapshot cutoff, возможен повторный fail-closed. Это корректнее неверных сумм.
- История `stats.json`, `stats_financial_anchor.json`, SQLite и `bot_state.json` **не мигрируется**; схема state и формат фин. anchor остаются прежними.
