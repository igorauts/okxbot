# OKX Grid Bot v0.6.7 — универсальное управление экземплярами

Версия основана на v0.6.6, с сохранением торговой логики LONG/CROSS, 25 следящих BUY, до 75 реальных TP, виртуальными TP, восстановлением состояния и статистикой. **Никаких изменений в алгоритме выбора ближайших 75 TP или генерации BUY** в этой версии нет.

## Сценарий управления

`okxbot` открывает интерактивное меню. Бот имеет уникальное имя, персональные файлы состояния, служебный systemd unit. Возможности:

| Действие | Новые BUY | Существующие BUY | SELL TP | Позиция | Экземпляр |
|---|---|---|---|---|---|
| **Пауза** | Не размещаются | Остаются (не перемещаются), могут исполниться | Обслуживаются, виртуальные восстанавливаются | Сохраняется | Жив |
| **Возобновить** | Продолжаются | Возвращается управление сеткой | Обслуживаются | Сохраняется | Жив |
| **Soft Stop** | Не размещаются | Отменяются по одной или небольшими партиями с проверкой | Обслуживаются, включая виртуальные | Сохраняется | Жив; можно возобновить |
| **Hard Stop** | Нет | Отменяются с подтверждением | Реальные TP отменяются; виртуальные не обслуживаются | **НЕ закрывается, без защитных TP** | **Завершён навсегда** |
| **Panic Sell** | Нет | Отменяются с подтверждением | Отменяются | Закрывается **рыночным reduce-only SELL** после полной сверки | **Завершён навсегда** |

**Panic Sell — это рыночная операция: может иметь проскальзывание и taker-комиссию.** Проверяет отсутствие другого активного бота по тому же инструменту, все известные биржевые ордера и равенство локальной и биржевой NET-позиции. Если невозможно точно доказать идентичность/результат ордера, процесс отказывается делать повторный рыночный POST вслепую. В таком случае может потребоваться ручная проверка и завершение на OKX.

**Hard Stop опасен при открытой позиции: биржевые TP снимаются, а позиция остаётся под риском ликвидации и без защитных лимиток!** Перед этим действием обязательно обдумайте управление оставшейся позицией. Клон после Hard Stop нельзя запустить на том же NET-инструменте, пока старая позиция остаётся: preflight audit должен обнаружить несоответствие.

## После Hard/Panic — новый бот-клон

Имя/статистика старого экземпляра сохраняются в реестре. Команда `okxbot start OLD` навсегда запрещена. Создание клона:

```
okxbot clone OLD NEW
```

Клон получает только торговые параметры и секреты для API из `.env` в отдельный защищённый каталог. Не копирует старые state/cycles/logs/PnL. Получает новую текущую цену OKX и при отсутствующей верхней границе пересчитывает капитал 1x. Всегда создаётся **с выключенной торговлей**, и запускается через `okxbot start NEW` после audit + явного подтверждения.

## Команды

```
okxbot
okxbot list
okxbot stats NAME
okxbot logs NAME -f
okxbot status NAME
okxbot pause NAME
okxbot resume NAME
okxbot soft NAME       # также: okxbot stop NAME
okxbot hard NAME
okxbot panic NAME
okxbot clone OLD NEW
```

Для Paused/Soft/Hard/Panic требуется буквальное подтверждение с именем. Для Hard/Panic — два подтверждения. Все запросы операций записываются атомарно в `state/control.json`, а отдельный торговый процесс под systemd читает этот запрос, проверяет биржевое состояние и сохраняет фазу в `state/control_ack.json`. Менеджер сам не отправляет заявки в OKX. Изменения фаз видны через `okxbot status` и `okxbot logs -f`.

**Остановка systemd извне не эквивалентна Soft/Hard Stop!** Позиции с виртуальными TP перестанут обслуживаться. Все штатные операции проводить через менеджер.

## Совместимость со старыми версиями

Установка менеджера не касается действующих `eth059` (v0.5.9) и `sol060` (v0.6.0). Их статистика и LIVE-логи доступны как раньше. **Команды Pause/Soft/Hard/Panic для них запрещены**, поскольку старые процессы не знают протокола команд; добавление пункта меню само по себе не обеспечивает безопасную отмену ордеров. Обновление старых работающих движков требует отдельной процедуры сохранения состояния и read-only сверки, а не копирования Python в работающий каталог.

## Установка менеджера на VPS

```bash
unzip -n /root/okx_grid_v067.zip -d /root
bash /root/okx_grid_v067/install.sh
okxbot list
okxbot
```

Установщик заменяет только `/usr/local/bin/okxbot` и кладёт новый код в `/opt/okx-grid-v067/`. Не меняет существующие systemd-службы и не перезапускает торговые процессы.

## Тестирование и статус готовности

Тесты в `tests/`: модульные симуляции pause, soft, hard, panic, отказов сети и подтверждений менеджера; регрессия grid/virtual TP и статистики. Тесты не посылают торговых API-запросов.

**Внимание: v0.6.7 с Hard/Panic ещё НЕ прошла интеграционные тесты на биржевом DEMO/изолированном аккаунте. До таких тестов считать функции Hard/Panic готовыми для реальной торговли нельзя.** Самое опасное состояние — завершение после Hard с открытой позицией и без TP. Не заменяйте живые процессы до проверки и резервного копирования состояний.


## Изменения v0.6.7

- **Исправлен индивидуальный учёт максимального отрицательного PnL каждого бота**. Общий equity аккаунта OKX не запрашивается и не учитывается. Логика ордеров, TP и частичных выходов не менялась.


### Старый фикс подтверждения запуска

В интерактиве `okxbot new` подтверждение теперь принимает **только** `yes` или `no` (не `да/нет`). Следующий этап, `START NAME`, по-прежнему требует английскую команду. Все команды подтверждения — на английском.

### Автоматическое освобождение частично исполненного BUY

По умолчанию: **60 секунд** после первого обнаруженного частичного исполнения и **рост текущего BID минимум на 5 GRID STEP выше цены BUY**. Эти значения можно задать в отдельном `config.json` каждого бота:

```json
"partial_buy_timeout_sec": 60,
"partial_buy_distance_steps": 5
```

При срабатывании бот:

1. Сохраняет намерение в торговом состоянии и **отменяет неисполненный остаток BUY** с отдельным подтверждением финального статуса OKX.
2. Учитывает изменение OKX от 1 июля 2026 года: после отмены частичного BUY OKX генерирует **прикреплённый TP на реально исполненное количество**. Бот связывает его **только по исходному `attachAlgoClOrdId`**, а не по цене или похожему объёму.
3. Если TP ещё не определён — **ждёт**, блокируя новые сделки, и не отправляет дублирующий SELL.
4. Если TP уже исполнился — дополнительный SELL не выставляется. Иначе бот отменяет TP и **дожидается окончательного подтверждения отмены**.
5. Если остаётся купленный объём, создаёт **один reduce-only MARKET SELL** на доказанный остаток с сохранённым `clOrdId` и восстановлением через REST; сетевой таймаут не приводит к повторной отправке POST.
6. После подтверждённого закрытия цикл становится `EXITED` и **освобождает уровень/слот**. Не прибавляется к `GRID PROFIT` и числу успешных TP. Фактическая реализованная прибыль/убыток и комиссии продолжают входить в **итоговый PnL** в отдельном показателе «PnL частичных выходов».

Условие применяется **только при росте** цены. Вниз по рынку частичные BUY не закрываются автоматически. Если исполнилась покупка целиком до отмены, бот возвращается к обычному TP и не выполняет принудительную продажу. Если биржа возвращает неясное состояние прикреплённого TP, бот предпочтёт ожидание, а не второй MARKET SELL. **Это намеренное fail-closed поведение.** Если исполнившийся объём меньше минимального торгового лота/некратен лоту, его нельзя продать точным MARKET SELL — бот не округляет объём вверх.

### Максимальная просадка

Максимальная просадка учитывается **отдельно для каждого бота** как минимум его уже существующего `ИТОГОВОГО PnL` (а не equity OKX): `ИТОГОВЫЙ PnL = GRID PROFIT + PnL частичных MARKET-выходов + нереализованный PnL`. Просадка = `max(0, -ИТОГОВЫЙ PnL)`; исторический максимум просадки — самый большой такой результат с первого замера v0.6.7. Это **убыток относительно нулевого PnL**, а не классический peak-to-trough equity drawdown. Пополнения/выводы аккаунта не влияют на эту метрику. Funding пока не включён.

Бот каждые **5 секунд** пересчитывает mark-to-market PnL по свежему публичному WS BID на основе последней **точно сверенной** полной статистики из фактических OKX fills/fees. При любом изменении финансово значимых данных цикла (BUY/SELL fill, закрытие и т.д.) частые замеры **приостанавливаются**, пока не будет собран новый достоверный снимок фактических исполнений (в течение ~60 секунд после изменений, при доступном OKX API). Полный расчёт истории остаётся каждые 10 минут при спокойной работе. Недостоверная приблизительная прибыль в просадку не записывается; кратковременные внутрипятисекундные минимумы могут быть пропущены.

Файлы на каждого бота: `state/bot_drawdown_v067.json` (история минимума и последний замер) и `state/bot_drawdown_anchor_v067.json` (проверенная база расчёта). Существующий `state/account_equity_drawdown_v066.json` **не используется и не удаляется**. Статистика `okxbot stats <name>` показывает строку `МАКС. ПРОСАДКА БОТА` с **последним сохранённым рекордом**, значением USD, % от расчётного капитала 1x и временем зафиксированного минимума; менеджер обновляет эти сведения из локального файла даже между 10-минутными полными отчётами. Мониторинг начинается с первого успешного LIVE-снимка на v0.6.7, предыдущие необработанные пики v0.6.6 восстановить невозможно.

### Без изменений

Механика сетки, число заявок, лимит 75 реальных TP и виртуальные TP, базовый минимальный TP с запасом 20% к двум maker-комиссиям, отсутствие учёта funding.

## Обновление уже работающих экземпляров `eth064` и `sol065`

**Никогда не заменяйте Python-файл работающего бота вручную.** Установить менеджер v0.6.7 можно отдельно, без остановки LIVE-процессов. Обновлять движок каждого экземпляра — индивидуально и с коротким простоем:

```bash
bash /root/okx_grid_v067/install.sh
bash /root/okx_grid_v067/upgrade_live_v067.sh eth064
bash /root/okx_grid_v067/upgrade_live_v067.sh sol065
```

Скрипт требует `UPGRADE eth064` или `UPGRADE sol065`, делает остановку systemd, резервное копирование `config.json`, **всего каталога `state/`**, службы и предыдущего движка; затем read-only audit и запуск v0.6.7. Если аудит не пройден, восстанавливает v0.6.6 **до первого запуска новой LIVE-версии**. Если после запуска LIVE возник сбой, старое торговое состояние **автоматически не откатывается**, поскольку биржа могла уже изменить ордера. Требуется ручной разбор. Скрипт не выполняет Soft/Hard/Panic и не закрывает позиции во время миграции.
