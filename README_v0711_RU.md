# OKX Grid Bot v0.7.11 — безопасная оптимизация и телеметрия

**Статус: опубликованный выпуск на базе LIVE-кандидата RC3.** База — v0.7.10. Включены исторические движки и тесты.

## Сверка позиции
- При необходимости повтора полной сверки первые интервалы 150, 300, затем 500 мс; проверки `orders-pending → attached/track/identity → positions` не пропускаются. При рассинхронизации новые BUY запрещены. 30-секундное ограничение и защита неопределённых POST остаются.
- Общий межпроцессный лимитер `/api/v5/account/positions` использует **8 запросов за 2,1 секунды**. В RC2 исправлено удержание `flock`: при исчерпании квоты освобождается lock, процесс ждёт и заново атомарно проверяет общий файл. Сам лимит не повышался.
- **Остающийся риск:** при отдельном `TimeoutError` всё ещё возможен fallback на локальную квоту 4/2,1 с, которая не учитывает все процессы. Эту архитектуру нужно исправлять отдельно. Предупреждения `ACCOUNT_POSITIONS_GATE_DEGRADED` в процессе LIVE-испытаний были, не скрываем их.

## Приоритет BUY
- Необязательная ротация реальных TP на базовом лимите уступает восстановлению недостающих BUY и выполняется в свободном проходе.
- Восстановление защитных TP, reconciliation, аварийные выходы, PANIC/HARD, anti-duplicate protections и фактическая SQLite-бухгалтерия сохранены.

## Диагностика
- `okx_latency_v0711.py` записывает `logs/latency_v0711.jsonl` асинхронно, с ограниченной очередью и ротацией; без ключей API и тел HTTP. Отчёт: `python3 -B okx_latency_report0711.py --root /путь/к/боту --hours 1`.
- Метрики: `http`, `rest_gate`, `positions_gate`, отдельные `positions_gate_lock_wait` и `positions_gate_quota_wait`, `position_reconcile`, `buy_post`, `buy_batch`, `ws_drain`, `loop_pass`.
- Большая задержка `fills-history` была измерена в фоновых REST-запросах. **Оптимизация её планировщика/кэша пока не включена.**

## Подтверждённые проверки
- 142 офлайн-теста: 45 (v076) + 13 (v078) + 22 (v079) + 19 (v0710) + 43 (v0711).
- После миграции на VPS: ETH079, ZEC0710, SUI0710-2, SOL0711 — активные службы, BUY 5/5, наблюдатели Burst/Execution, версии 0.7.11, сравнение SHA256 с RC3, SQLite quick_check и 0 ожидающих бухгалтерских циклов по локальному статусу. Независимая повторная сверка OKX API при этом аудите не выполнялась.
- На общем RC3 наблюдались медианы времени `positions_gate` около 450–566 мс (в разных временных окнах); эти показатели **не являются гарантией** скорости, ускорение зависит от конкуренции за общую квоту.

## Установка
GitHub Release не обновляет запущенные экземпляры. Исторический `install.sh` относится к старой версии и **не годится** для v0.7.11. При обновлении LIVE обязательны проверка текущего состояния, резервная копия, штатная миграция config/state, проверка systemd `ExecStopPost`, запуск только своего экземпляра и версионированных наблюдателей. Не подменяйте запущенный движок простым копированием.

## Запланировано, не включено
- Hot Settings — изменение всех настроек без остановки.
- Несколько ботов на одной паре одного NET-аккаунта OKX (общий учёт позиции/ownership).
- Устранение `ACCOUNT_POSITIONS_GATE_DEGRADED` fallback-риска; сокращение бесполезных REST-сверок; оптимизация фонового `fills-history`.
