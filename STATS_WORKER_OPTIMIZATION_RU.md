# v0.7.33 · оптимизация StatsWorker · офлайн RC1

Основа: v0.7.32 RC2 (SHA256 исходного ZIP `49e0ac23e020c109a00511ae7a43cc00193355abac153d7ce263399726a5a9e4`), работающая на ZEC. Изменения касаются финансовых расчётов и диагностики, а не BUY/SELL/PANIC/FIFO/WS. SHA256 движка изменён, поэтому **новая версия движка 0.7.33**, а не ложный maintenance-пакет с идентификатором 0.7.32.

## Файлы одного бота

| Файл | Кто меняет | Роль в StatsWorker |
| --- | --- | --- |
| `state/bot_state.json` | торговый цикл | читается как зафиксированный state; StatsWorker не перезаписывает |
| `state/cycles.sqlite` | компактор завершённых циклов | снимается список исторических циклов, не удаляется |
| `state/fills.sqlite` | FillStore + API для недостающих fills | фактические цены, комиссии, объёмы; новые записи только по подтверждённым биржевым fills |
| `state/pnl.sqlite` | PnLLedger | точный учёт закрытий, при сверке возможно дополнение недостающих завершённых циклов; ничего не стирается |
| `state/stats.json` | StatsWorker | атомарно **заменяется** при успешном полном отчёте, предыдущий отчет не накапливается в файле |
| `state/stats_financial_anchor.json` | StatsWorker | атомарно заменяется вместе с stats; фин. подпись, PnL, время именно снимка |
| `state/grid_reference.json` | финансовая отчётность | фиксированная стартовая цена/капитал; если ещё отсутствует, может создаться единожды |
| `state/runtime_stats.json` | heartbeat | StatsWorker читает uptime; сам файл обновляет другой код |
| `state/bot_drawdown.json` | sampler | отчёт читает историческую max drawdown; отдельный диагностический канал |

В `stats.json` намеренно присутствуют `performance` и `performance_v0724` — **два одинаковых поля для совместимости старых клиентов**, но не две SQLite-базы, не два независимых расчёта и не удвоение финансовых значений.

## Где была нагрузка

`full_stats_snapshot()` создавал `fill_by_id` полным обходом всех fills *на каждом цикле*. При 7 502 циклах и 12 303 fills ZEC это около 92 млн шагов только индексирования. Теперь словарь создаётся **один раз до цикла**, а функции распределения MARKET сохраняют оригинальный порядок fills, точные комиссии и Decimal.

Дублированный `_last_24h_profit()` для текста и `performance` вычисляется один раз и передаётся в оба представления, без изменения его алгоритма.

Каждый успешный расчёт выдаёт `⏱ StatsWorker: total=... capture=... fills=... calculation=... ledger=... report=... write=... cycles=... fills_count=...`. Это сообщение не изменяет торговое состояние, не вызывает API и не создаёт отдельный файл.

## Офлайн замеры чистой функции

Синтетические полностью закрытые циклы: каждый BUY $100, SELL $101, две точные комиссии по -$0.01. Сравнение непосредственно v0.7.32 RC2 и нового исходника с **полностью равными словарями результата**:

| Циклы | Fills | 0.7.32 RC2 | Новый расчёт |
|---:|---:|---:|---:|
| 250 | 500 | 0.019 с | 0.004 с |
| 1 000 | 2 000 | 0.279 с | 0.016 с |
| 3 000 | 6 000 | 5.710 с | 0.058 с |
| 7 502 | 15 004 | не выполнялся | 0.167 с |

Это **не** результаты LIVE ZEC и не полный цикл с GET, SQLite, архивом и отчётом. Снижение загрузки VPS можно подтвердить только после управляемого теста на реальном объёме.

## Защита

Не изменены торговые алгоритмы, лимиты SELL/BUY, MARKET SELL, PANIC, стратегия, FIFO и подписки WS. Требования полной истории fills, точной комиссии и сверки `pnl.sqlite` сохранены; неизвестные данные по-прежнему блокируют публикацию. Старый SHA 0.7.32 остаётся в engine_manifest, новый 0.7.33 имеет отдельную идентичность.

Сейчас **только офлайн RC1**: никаких изменений VPS, открытых позиций или GitHub. DOOD по-прежнему отдельно закрывается PANIC после разрешения его существующего `PENDING`.
