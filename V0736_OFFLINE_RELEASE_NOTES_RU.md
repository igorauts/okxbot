# OKX Grid Bot v0.7.36 — OFFLINE RC1 (НЕ УСТАНОВЛЕНО В LIVE)

## Границы релиза

Пакет `0.7.36` — **только трёхкомпонентная версия**. Торговый движок остаётся **`0.7.35`**: `okx_bot.py`, спецификация контракта, FIFO/quota и схема торговых intents не изменены. `Priority FIFO` не включён, действует `mixed-fifo`. Funding Collector и TP cooldown не трогаем. Ранее завершённые боты и их архивы — read-only.

### P0: новые боты / Reader

- В исходниках закреплён уже проверенный на VPS код `new`/`clone`/`start`, обновляющий реестр Reader через GET-free Unix IPC и проверяющий регистрацию пары до первого LIVE запуска.
- `clone` берёт актуальный общий account-env, не наследует старые Reader-настройки архива. Четырёхкомпонентных maintenance-релизов нет.
- Тесты создания, регистрации, ошибки неизвестной пары, NET-совместимости и отсутствия дополнительной GET-квоты.

### P1: Telegram BYPASS / RECOVERED

- Для активного RUN-бота при устойчивом отсутствии правильного Reader socket / `mixed-fifo` либо отсутствующей регистрации пары в работающем Reader формируется **один BYPASS на эпизод** после 60 секунд; после подтверждённого успешного IPC и устойчивого восстановления — **один RECOVERED**.
- Краткий перезапуск Reader уже покрывается Reader DOWN/RECOVERED; не создаёт второе BYPASS-уведомление.
- Чисто временный прямой GET после `PositionReaderEmpty` невозможно надёжно отличить от отказа Reader по нынешнему телеметрическому полю `outcome=unavailable`; поэтому **не заявляем аварийный BYPASS только по таким ошибкам** (избегаем ложного спама). В общем экране это показано как диагностическое состояние, не как доказанное повреждение.

### Дополнительная функция: Reader Diagnostics — одно меню на весь аккаунт

- В основном меню: `🔎 Reader Diagnostics (весь аккаунт)`; дополнительная CLI-команда: `okxbot reader-diagnostics`.
- Один общий экран: IPC health, список зарегистрированных пар, общий GET/quota counters и `pending`; затем строка каждого активного бота с его состоянием Reader, успешными/неуспешными IPC и прямыми `/account/positions` GET за доступный хвост последних 60 минут.
- **Только локальный Unix IPC + файлы телеметрии + systemd state**. Нет API GET, POST, изменений конфигурации и других действий с биржей.
- Исторический хвост до 32 МиБ на бот, с явным предупреждением об усечённом окне; Telegram ограничен хвостом 1 МиБ на бот каждые 30+ секунд.
- Показатель `SUSTAINED FALLBACK` диагностический: не доказывает неизвестную биржевую позицию и не участвует в торговых разрешениях.

### P2

- Удалено неправильное продолжение «дополнительные ошибки за окно»: после длительной тишины новая ошибка получает метку нового эпизода, а десятиминутное ограничение уведомлений сохраняется.
- Восстановлен исполняемый режим `0755` для двух CLI-скриптов (`okx_live_upgrade.py`, `rollout_preflight.py`), включая ZIP mode bits.
- Старый аудит NEAR, cooldown TP, Funding и Priority FIFO сознательно вне scope.

## Раскатывание (НЕ автоматически)

Требуется отдельная проверка SHA на VPS, полный локальный preflight, backup shared Reader/manager и реальных Telegram файлов, поэтапный controlled restart **только Reader** и Telegram-монитора, повторное сравнение PID всех активных торговых процессов, успешный IPC health со списком пар, проверка `okxbot reader-diagnostics`. **Без stop/start торговых ботов и без новых биржевых запросов**. Любой отказ — STOP и ручной аудит/откат; GitHub release только после LIVE PASS.

## Проверки

Источник: опубликованный финальный ZIP v0.7.35 плюс три exact-file LIVE patches `new`/`clone`/Reader IPC, ранее проверенные на реальном VPS. Новые тесты содержатся в `tests/test_reader_diagnostics_vnext.py`, плюс ранее созданный `tests/test_newbot_reader_autoreg.py`. Старые исторические тесты четырёхкомпонентных версий заменены динамическими инвариантами. Торговый движок сравнивается побайтово с исходным ZIP.
