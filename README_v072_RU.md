# ETH OKX Grid Bot v0.7.2 — защита ближайшего BUY при Grid Following

**Релиз v0.7.2 опубликован после успешного перехода ETH-USDT-SWAP на LIVE 14 октября 2026 года.**
Инструкции ниже описывают ранее проведённый контролируемый переход с v0.7.1; SOL не затрагивается.

## Причина обновления: 14 октября 2026, 19:01:50 UTC

При BID 2430.00 бот v0.7.1 поставил BUY 2417.50 и отменил BUY 2430.00. Отмена стала возможной потому, что цена 2430.00 вышла из нового набора 25 желаемых уровней после сдвига вниз. Старый код сортировал `obsolete` по цене и удалял первый, не учитывая дистанцию до реального BID. Кроме того, таймер `BUY_BUFFER_COOLDOWN` сбрасывался только при движении сетки вверх, а не вниз.

Последствие: пропал потенциальный вход BUY 2430.00 и соответствующий будущий TP 2432.75.

## Что меняется

- `plan_buy_buffer_cleanup`: нельзя отменять `BUY_LIVE` в пределах **трёх шагов GRID_STEP** от свежего BID (в текущей ETH-конфигурации +/- **$1.50**); правило работает выше и ниже BID. Остальные кандидаты на отмену сортируются по убыванию расстояния от рынка.
- Таймер очистки **1.5 секунды** сбрасывается при любом сдвиге grid top, как вверх, так и вниз.
- Перед каждой отменой повторно считываем свежий BID и пересчитываем желаемую сетку. Если цена вернулась к ордеру, его нельзя отменять.
- Если 30 BUY заполнены и нет безопасного кандидата на отмену, новые BUY откладываются. Лимит 30 не нарушается.
- Вся механика real/virtual SELL TP и MARKET-агрегации осталась без изменений. Остальные REST/позиционные проверки сохранены. Дополнительный тикер запрашивается только при необходимости очистки, а не на каждом проходе.
- Новый журнал `BUY_CANCEL_PROTECTED` для расследования сохранённых уровней; расширенный `BUY_BUFFER_CLEANUP` теперь включает текущий BID.
- Миграция 0.7.1 -> 0.7.2: сохраняет все циклы, `aggregate_exits`, виртуальные TP и PnL; атомарное сохранение state и файл `state/bot04_state_before_v072.json`.

### Оговорка

Защитная зона **3 шага** — выбранная консервативная политика; это не математическая гарантия заполнения ордера. Ордер, отдалившийся от рынка больше трёх шагов, может быть отменён как устаревший. Биржевой fill может совпасть по времени с cancel; существующая сверка и журнал намерений об отмене продолжают отвечать за такое состояние.

## LIVE-переключение — только после проверки

1. Резервная копия полного `eth064/state` и настроек systemd **после остановки ETH**, пока работающий движок не пишет в файлы.
2. Проверенная по SHA256 версия `okx_bot072.py` в `/root/okx/eth064` без запуска второго экземпляра.
3. Проверка systemd `ExecStart` только для ETH, контроль PID, запуск ровно одного экземпляра, выдержка 15–30 секунд.
4. Проверка `STATE_UPGRADED 0.7.1->0.7.2`, сохранения всех циклов, позиции OKX и корректных TP/BUY (без неразрешённых ордеров).
5. После запуска не откатывать просто на 0.7.1: торговое состояние уже изменилось и могли пройти новые сделки. При проблемах остановить ETH, сохранить диагностику, сделать отдельный план по биржевой сверке.

SOL v0.6.10 нельзя менять.

CLI-менеджер можно адаптировать отдельно через `python3 prepare_manager_eth072.py` (dry run) и `--apply` после сверки, без рестарта торгового процесса.

**Важно:** наличие 150+ виртуальных TP означает, что остановка ETH лишит их автоматического сопровождения. Выполняйте контролируемое переключение максимально быстро и без посторонних операций.

## Контролируемая команда переключения (после аудита)

`bash switch_eth_v072_live.sh --live` — выполняется на VPS, проверяет свежий (<15 мин) успешный файл аудита, делает OFFLINE backup после остановки ETH, переключает **только** ETH, проверяет состояние. Не запускать, пока аудит не пройден. При ошибке **после** старта v072 не делает автоматический даунгрейд состояния.
