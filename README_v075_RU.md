# OKX Grid Bot v0.7.5 — релиз 16 октября 2026

**Три изменения:** меньше сохранений большого JSON во время массовой сверки исполнений; улучшенная Telegram-сводка `/status`; корректная отмена избыточных BUY **снизу вверх, начиная с самой низкой цены**.

## Торговый движок

`okx_bot075.py` сохраняет LONG/CROSS, лимитные BUY, прикреплённые биржевые SELL TP и виртуальные TP. Фиксированный BUY-буфер +5 и защита ближайших 5 шагов не менялись. Реальные SELL TP по-прежнему ограничены старой формулой `REAL_TP_TARGET + (TARGET_BUY + 5)` (для TARGET=25 это 25+30=55). При освобождении BUY-буфера до целевого количества отменяются **самые нижние подтверждённые BUY**, при этом BUY_PARTIAL, PLACING и CANCELING не попадают в механизм обычной очистки. Перед каждой отменой заново проверяются BID, список BUY и конкретный `ordId`.

## JSON и восстановление после сбоев

Сохранения подтверждённых биржевых фактов объединяются на время сверки. Перед каждым новым POST подтверждённые факты сбрасываются на диск. Торговое намерение (`PLACING`, `CANCELING`, ID) записывается надёжно **до** отправки запроса; сетевой таймаут восстанавливается сверкой по первоначальному client ID без слепого повторного размещения. JSON остаётся атомарным, с `fsync` файла и каталога. Повтор сверки через 500 мс, BUY pacing 50 мс, межпроцессное ограничение запроса account positions.

## Telegram

Внешний монитор `okx_telegram_monitor.py` читает существующие отчёты и журнал событий, не имеет доступа к биржевым ключам и не изменяет торговое состояние. Алерты: критические ошибки, проблемы синхронизации, остановки сервиса, зависшие heartbeat, общий AUTO SOFT STOP. Сводка в 09:00 по Santiago, `/status` для ETH/SOL с PnL, комиссией, объёмом, открытой позицией, просадкой и историческим максимумом позиции. Время `running` считается с первого запуска самого бота. Исторический максимум позиции берётся через имеющийся на VPS `okx_position_peak.py`; при отсутствии помощника — `н/д`. Пути двух экземпляров в файле заданы как конфигурация для текущего развёртывания, при других именах/каталогах их нужно изменить.

## Отдельные файлы и проверки

- `okx_bot075.py` — единый движок; именно hotfix r1 его код сейчас работает на ETH/SOL.
- `okxbot.py` + `okx_ui074.py` — CLI-менеджер и read-only экраны с распознаванием v0.7.5; публикация сама по себе **не обновляет установленный на VPS менеджер**.
- `okx_telegram_monitor.py` — монитор Telegram.
- `v075_checks/` — 34 unit-теста, отдельный offline replay-стресс.

Проверки без API, без LIVE:

```bash
python3 -m py_compile okx_bot075.py okxbot.py okx_ui074.py okx_telegram_monitor.py
python3 -m unittest discover -s v075_checks -p 'test_*.py' -q
python3 v075_checks/stress_v075_reconcile.py
```

Эталон `v075_checks/original_okx_bot074.py` нужен только для сравнения AST-функций и не запускается. В `v075_checks/` синтетические ордера, не персональные данные пользователя. Дополнительные ограничения и выводы в [RELEASE_NOTES_v075.md](RELEASE_NOTES_v075.md).

**Публикация GitHub, обновление файлов в локальной копии репозитория и выкладка архива не затрагивают уже торгующие сервисы.** Не запускать на LIVE обычные `install.sh`/upgrade-скрипты только ради публикации.
