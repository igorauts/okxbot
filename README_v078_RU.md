# OKX Grid Bot v0.7.8 — Monitoring Accuracy & Terminal Accounting

Релиз 16 октября 2026 года. Включает изменения **v0.7.7 и v0.7.8**, поскольку предыдущим опубликованным GitHub Release была v0.7.6. ETH077 и SOL077 были проверены на LIVE с v0.7.8; публикация репозитория **не меняет** работающие systemd-службы и торговые состояния на VPS.

## Терминальные финансовые отчёты (из v0.7.7)

- После подтверждённого `PANIC_DONE` рассчитывается конечный **торговый** PnL по фактическим BUY/SELL исполнениям OKX и комиссиям. Ранее рассчитанный `GRID PROFIT` не переписывается; прибыль/убыток PANIC SELL показывается отдельно. При недостатке подтверждённых данных окончательный результат не объявляется.
- После `HARD` (режим `RETIRED`) фиксируются сеточная прибыль и исторический снимок оставшейся позиции, цены и нереализованного PnL **на момент остановки**. Итогового реализованного PnL у HARD нет: позиция не закрыта.
- Сохраняется **полный исторический отчёт** из `state/stats.json`; терминальный блок добавляется в конце и не скрывает прежние метрики.
- Отдельная GET-only операция может пересчитать старые завершённые экземпляры. Служебный retry поддерживает v0.7.7 и v0.7.8. Финальные вычисления не должны отправлять торговых POST.

## Менеджер и Telegram

- Менеджер `okxbot.py` выбирает новейший **реально установленный** движок по числовой версии и проверяет его `VER`. Файл `engine_manifest.json` перечисляет зависимости движка. Старый мастер `okx_setup068.py` при создании через `okxbot` остаётся совместимым: после мастера менеджер заменяет движок **только у нового, ещё не запущенного экземпляра**. Для последующих версий нужен новый движок и его запись в манифесте, но не обязательно новый менеджер.
- Telegram `/status` показывает только активных ботов; адресный `/status ИМЯ` позволяет открыть статистику завершённого бота.
- Монитор сам обнаруживает новые экземпляры через реестр и systemd, а не через прописанные вручную имена ETH/SOL.

## Точность и стоимость мониторинга (v0.7.8)

- Старый `PARTIAL_ATTACHED_TP_DISCOVERED` генерируется **только при подтверждённом частичном BUY**; иначе `ATTACHED_TP_DISCOVERED` помечается как неподтверждённый на момент обнаружения TP. Торговые решения и механика attached TP не изменены.
- Burst/Execution Observer v0.7.8 определяет периоды BUY ниже цели по меткам сообщений **торгового движка**, а запаздывающее состояние JSON трактует как отдельный снимок. Это не прямой запрос количества ордеров на OKX.
- Наблюдатели работают отдельными локальными процессами без OKX API и без доступа к `.env`. Предусмотрены `Nice=10`, `IOSchedulingClass=idle`, `CPUQuota=5%`, `MemoryMax=96M`, буферизация событий и счётчик потерь диагностических записей. Они не должны блокировать торговый движок.

## Версии и ограничения

- Главный файл торгового движка: `okx_bot078.py`, `VER='0.7.8'`, SHA256 `76ae3c06cf6b16b6c1b40a7b0bcfbf8e392ceb493bb7aa6c18fdff663ee938f8`.
- В репозитории сохранены `okx_bot076.py` и `okx_bot077.py` для совместимости и истории.
- **Не изменялись:** политика рыночного выхода `virtual_escape`, торговая стратегия BUY/SELL/TP, Grid Following, скорость запросов и торговые ограничения.
- LIVE-боты не нужно и нельзя обновлять простым копированием файла во время торговли. Используйте отдельную проверенную процедуру с бэкапом, GET-only сверкой, остановкой одного экземпляра и контролем нового state. Публикация GitHub ничего на LIVE не меняет.
- После HARD открытая позиция остаётся без TP; PANIC SELL выполняется по рынку с возможным проскальзыванием и убытком.

## Проверки и воспроизведение

Запускать в корне клона репозитория:

```bash
python3 -B -m unittest discover -s v076_checks -p 'test_*.py' -q
python3 -B -m unittest discover -s legacy_v077_tests/stage/v077_checks -p 'test_*.py' -q
python3 -B -m unittest discover -s v078_checks -p 'test_*.py' -q
```

При публикации должны пройти 45 + 12 + 13 тестов. Отдельно проверяется идентичность исходников из LIVE и в релизном архиве.
