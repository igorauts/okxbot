# OKX Grid Bot v0.7.6 — LIVE ETH/SOL, 16 октября 2026

Релиз включает новый движок `okx_bot076.py`, обновлённый Telegram-монитор, совместимый менеджер и мастер создания ботов. BTC остаётся поддерживаемым инструментом движка, но на момент релиза не заявлен как протестированный этим движком на LIVE.

## Что изменилось после v0.7.5

**Главное — надёжность двух ботов на одном аккаунте.** Общий лимитер запросов `/api/v5/account/positions` теперь сам восстанавливает повреждённый файл и не зависает из-за меток времени из будущего. Если невозможно использовать общий lock/file, каждый процесс переходит на ограниченный резервный лимитер; уведомление попадает в журнал и Telegram. При неисправности лимитера возможны дополнительные ограничения OKX (429), но файл лимитера больше не должен навечно блокировать сверку двух ботов.

**Telegram:** отдельные сообщения о рыночных закрытиях (`AGG_MARKET_INTENT`, `ACK`, `REJECTED`, `TERMINAL`) со статусом, объёмом и средней ценой исполнения, когда биржа их предоставила. События разных MARKET-ордеров не подавляются общей задержкой 600 секунд. Реализованный PnL в уведомлении не придумывается.

**Неопределённый POST:** без изменения принципа «никогда не повторять неопределённый запрос вслепую» история проверяется до шести суток; неуспешная или неполная сверка оставляет ордер неопределённым.

**BUY no-churn (r2):** в v0.7.5 r1 при BID точно на уровне BUY была возможна повторяющаяся постановка самого нижнего BUY и почти мгновенная отмена. В v0.7.6 включён LIVE hotfix r2: при заполненных 25 BUY нижние уровни не добавляются только ради восполнения заново рассчитанной сетки. Отмена излишков продолжает идти **от минимальной цены вверх**, с защитой пяти ближайших шагов.

**Параметры сетки не менялись:** 25 активных BUY с резервом +5; лимит реальных TP 25 + (25 + 5) = 55 для конфигураций с целью 25. P1 `virtual_escape` и P4 скоростные изменения не трогали. Рыночное закрытие может произойти ниже входа после отката цены — это осознанно неизменённая стратегия.

## LIVE-статус и проверка

После установки 16.10.2026 на `eth064` и `sol065` обе службы были активны, без перезапусков, BUY 25/25, Telegram-монитор active. У обоих движков SHA256:

`218024dc611a85d076d1ce40d924ca555f21300b861663b7f0876ac729329481`

Установка на существующие LIVE-процессы была отдельной контролируемой процедурой; **GitHub-релиз ничего на VPS не меняет**. На VPS ради сохранения прежнего systemd ExecStart новый исходник 076 лежит под старым именем `okx_bot075.py`; именно `VER='0.7.6'` и state.version определяют реальную версию. В новой установке/клоне используется файл `okx_bot076.py`.

Изолированные тесты, не обращающиеся к торговому API:

```bash
python3 -m unittest discover -s v076_checks -p 'test_*.py' -q
```

45 тестов проверены на зафиксированном движке. Тесты включают оригиналы предыдущих движков только как неподключаемые AST-эталоны.

## Ограничения и меры безопасности

Поддерживаются BTC-USDT-SWAP, ETH-USDT-SWAP и SOL-USDT-SWAP в LONG/CROSS с post-only BUY и прикреплёнными лимитными TP. Список инструментов, возвращаемый `GET /account/instruments`, сам по себе **не означает право данного API-ключа торговать каждым инструментом**. Отдельный лимитер `/account/positions` в аварийном режиме обеспечивает ограничение на процесс, а не на все возможные сервисы и машины.

Исторические observer074-модули остаются специфичными для v0.7.4; независимый Telegram-монитор обновлён для 076. Никаких реальных ключей API, бот-состояний, баз SQLite или логов в репозитории нет.

> Для уже работающих ботов нельзя просто перезаписать `state/bot04_state.json` или восстановить старый бэкап поверх новых исполнений. Релиз предназначен прежде всего для версионирования проверенного исходника и безопасного создания новых экземпляров.
