# OKX Grid Bot v0.6.10 — инструкция

Версия 0.6.10 сохраняет параметры стратегии, истории и SQLite-базы v0.6.9. Код движка `okx_bot0610.py`; проектный менеджер `okxbot.py` обновляется только в **клоне репозитория** скриптом `prepare_repository_v0610.py`.

## Порядок работы

1. Распаковать архив в отдельный каталог, **не в живые каталоги ETH/SOL**.
2. Выполнить `python3 test_v0610_safety.py` и `python3 verify_real_import.py` из среды с установленной библиотекой `websocket-client`.
3. Подготовить отдельный клон GitHub v0.6.9, применить `python3 prepare_repository_v0610.py /путь/к/клону`. Запустить `python3 -m unittest discover -s tests -p 'test_*.py' -q` в клоне.
4. Только после успешных тестов подготовить установку обоих LIVE-ботов: резервные копии при остановленных процессах, READ_ONLY сверка и согласованное изменение systemd drop-in с приоритетом **выше** существующего `90-v069.conf`.
5. Ни state-файлы, ни SQLite, ни общую SOFT-блокировку не удалять и не сбрасывать. При миграции state 0.6.9 создаётся `state/bot04_state_before_v0610.json`.

### expTime

`expTime` ограничивает **время приёма заявки биржей**, а не время жизни LIMIT-ордера. Его дата записывается до отправки HTTP POST. При неопределённом ответе бот проверяет точный `clOrdId`, историю и часы биржи; новый механизм освобождения работает только для намерений, созданных в v0.6.10. После истечения 120 секунд и трёх полных отрицательных проверок с промежутком не менее 20 секунд запись может быть освобождена. Это подтверждение по нескольким источникам, **не абсолютная гарантия отсутствия ордера**, поэтому при недоступности истории или рассогласовании позиции бот остаётся в безопасном режиме.

### Telegram

Telegram-монитор независим от торгового движка и работает отдельной systemd-службой **один на оба бота**. Без токена бот не получает и не отправляет уведомления. Подключение выполняется после предоставления пользователем `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в закрытом конфигурационном файле `/etc/okxbot/telegram.env` с правами `0600`:

```
TELEGRAM_BOT_TOKEN=***
TELEGRAM_CHAT_ID=***
```

При запуске он читает новые строки `logs/bot04_events.jsonl` обоих ботов, проверяет `systemctl is-active`, отвечает только на `/status` из разрешённого чата и отправляет общую сводку в 09:00 по часовому поясу `America/Santiago`.

Монитор не использует биржевые API-ключи, не выставляет ордера, не принимает команды изменения режимов и не вмешивается в торговлю. Состояние доставленных уведомлений хранится отдельно в `/var/lib/okxbot/telegram_monitor_state.json`.

Сервисный unit-пример — `okx-telegram-monitor.service.example`. Создание / включение службы и настройку секретов выполнять только после явного согласования.

### Что не входит

Предварительные проверки маржи, оптимизация SQLite, пакетные BUY, Amend и пробуждение торгового цикла по BID намеренно отложены. Оптимизации — для 0.7.0.
